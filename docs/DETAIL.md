# maw 看板

把本机 [maw](https://github.com/) 的多 Agent 看板接进 DeepSeek Harness 会话。maw 负责拆任务、派 worktree、管领取与合入；这个插件只做一件事 —— **把它的状态显示出来**。

## 为什么只读

maw 的写命令（`next --claim`、`submit`、`merge`、`block`、`prune`）会改任务状态、动 worktree、删分支。这些动作需要明确的上下文与人的判断，不该由一个看板插件在后台代劳。所以本插件只执行白名单内的只读子命令：

```
board · task list · task show · agents · project list · iteration list · node list · stats
```

任何不在表内的调用在执行器入口就被拒绝。

## 界面

### 会话视图标签

会话主区顶部在「对话」「轨迹」旁边多一个「看板」标签，点开即看板。它和对话共用同一块区域，不占额外屏幕。

从哪个工作区进来的会话，就看哪个工程：DSH 把每个工作区的会话放在按路径编码的目录下，插件据此把会话 id 反查成工作区路径，再与 maw 登记的工程比对；命中就把工程筛选默认选上。只登记了一个工程时，从其他工作区进来也默认落到它。

两个标签页：

- **看板** —— 以**任务状态**为泳道分组（可开工 / 进行中 / 合入中 / 待办 / 阻塞 / 已完成 / 已取消），卡面保留原泳道名与优先级。顶部四个筛选器（项目 / 泳道 / 状态 / Agent）与「显示已完成」开关。右侧栏列出风险与问题，按严重程度着色。
- **拓扑** —— 依赖 DAG，视觉与 maw board 一致：节点是 200×98 的卡片（左侧状态色条、id + 状态徽章、两行标题、负责人与 `P优先级`），连线为平滑贝塞尔并带中点圆点与箭头，视图外依赖画成虚线桩节点。横轴是依赖层级，悬停高亮直接相连的上下游；点击节点才在右侧打开详情，未选中时不占位。

### 任务详情

状态、负责人、泳道、优先级、合入序、尝试次数、依赖与上下游、写范围、读范围、验收条目、验证命令、分支、工作树、阻塞原因。

## 快捷键

按标签位置切换会话视图，序号与标签栏顺序一致（当前为 对话=1、轨迹=2、看板=3）。

| 运行环境 | 组合 |
|---|---|
| Desktop | `⌘1/2/3`、`⌥1/2/3`（Windows、Linux: `Ctrl+1/2/3`、`Alt+1/2/3`） |
| Web 浏览器 | `⌘⌥1/2/3`（`Ctrl+Alt+1/2/3`） |

浏览器把「单个修饰键 + 数字」留给自己的标签页切换，因此在 Web 运行时登记这些组合会被 shortcuts 服务直接拒绝；插件只在那两个平台上回避，Desktop 保持不变。

设置 → 快捷键 里每条命令的标题会跟着标签名走（如「切换到 看板」），按位置调整后不会出现序号与内容对不上的说明。

实现上，切视图没有公开 API（视图选择是 ui-conversation 自己的 store），所以借用标签栏上的 `data-conversation-tabs` —— 这是产品自己标注的稳定锚点 —— 按位置触发点击。

## MAW 模式

模式选择器里的一个 agent preset（id `maw`），与「标准模式」同构，只换了 persona 与工作流。

- **拆题**：题卡必须带 `id` / `title` / `writeScope` / `acceptance` / `verify`；`acceptance` 与 `verify` 是 maw 的硬要求，缺了压不进去。
- **压入**：`maw_plan_push` 把清单渲染成 blueprint 写到 `.multiagent/blueprint.maw-<时间戳>.toml`，先跑 `maw plan check`，再按 `apply` 决定是否 `plan apply --yes`。文件名带时间戳，不覆盖既有蓝图；apply 是增量合入，不带 `--reset`。
- **团队协作**：预设切到 MAW 时自动 `agentTeams.setEnabled(agent, true)`。因为切换事件是在会话写入过程中发出的，插件延后一拍再开，避免 append 重入；失败只记诊断。

诊断入口：`GET /dsh-maw/api/mode` 返回 `{ presetId, log }`，`log` 里每条记录包含触发来源、判定依据、团队开关结果。

## 三个工具

Agent 在会话里可以直接调用，拿到与界面一致的数据：

| 工具 | 用途 |
|---|---|
| `maw_board` | 看板摘要与筛选后的任务列表 |
| `maw_task` | 单个任务的完整详情 |
| `maw_deps` | 依赖拓扑；传 `focus` 看某任务的邻域 |

## maw 运行时

maw 是背景依赖而不是打包内容：二进制约 18MB 且分平台，塞进插件会让每个用户都下载所有平台。

安装器（`lib/maw-install.js`）做四件事：解析本平台的 release 资产 → 下载 → 按 `checksums.txt` 校验 sha256 → 解包安装并跑 `--version` 自证。官方包里的文件名是 `maw_<版本>_<平台>_<架构>` 而不是 `maw`，所以解包后统一改名。

失败策略是「宁可不装」：取不到 checksums、或 sha256 不匹配，直接中止并报错，不会留下一个无法验证的二进制。

`maw init`（在业务仓库里生成 `.multiagent/`）**不自动执行** —— 它会写用户的仓库，属于显式动作。

## 数据流

```
浏览器（看板 / 拓扑 UI）
      │  GET /dsh-maw/api/{board,graph,task,refresh}
      ▼
Host 半边  ──  spawn  ──►  maw <只读子命令> --json
      │                          │
      └────── 归一化 + 建图 ◄─────┘
```

Host 侧对命令结果做 5 秒缓存并合并并发请求，所以前端轮询不会反复拉起进程。

## 降级行为

| 情况 | 表现 |
|---|---|
| maw 未安装 | 界面提示未找到 maw 并给出查找过的路径，不白屏 |
| 当前目录不是 git 仓库 | 退回配置的项目路径，再退回 maw 项目登记 |
| 命令超时或输出异常 | 该数据源标为降级，其余部分照常渲染 |
| 依赖图有环 | 红色虚线标出并单独列出，其余节点正常渲染 |
| 依赖指向不存在的任务 | 单列为悬空依赖，不静默丢弃 |

## 已知限制

- 绑定 maw 0.4.1 的 JSON 字段名。
- 拓扑图超过 `maxGraphNodes` 时默认只渲染未完成子图。
- 不做 `maw status report` 心跳上报（写操作）。
