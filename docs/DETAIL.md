# Multi-Agent Workspace

把本机 [maw](https://github.com/) 的多 Agent 看板接进 DeepSeek Harness 会话。maw 负责拆任务、派 worktree、管领取与合入；这个插件只做一件事 —— **把它的状态显示出来**。

## 为什么只读

maw 的写命令（`next --claim`、`submit`、`merge`、`block`、`prune`）会改任务状态、动 worktree、删分支。这些动作需要明确的上下文与人的判断，不该由一个看板插件在后台代劳。所以本插件只执行白名单内的只读子命令：

```
board · task list · task show · agents · project list · iteration list
```

任何不在表内的调用在执行器入口就被拒绝。白名单只收「maw 里真实存在且会输出 JSON」的只读命令：`node` 在 0.5.0 被移除、`stats` 是不输出 JSON 的父命令，两条都已从表里拿掉。

唯一不经过 maw 写命令的主动作是看板上的**启动**按钮：它不改任务状态、不领取、不动 worktree，只是新建一个 MAW 模式的 DSH 会话，把「按依赖顺序开工」的指令投进去。maw 侧真正领取与合入仍由 maw worker 负责。

## 工程隔离

一台机器可以登记多个 maw 工程。`maw board` 是跨工程的全局看板（实测本机 6 个工程、389 题），`task list` / `agents` 则是按目录（`-C`）隔离的。插件所有入口都收口到「当前会话所属的那个工程」：

- **界面**：工程由会话工作目录决定（真实 cwd 优先，走 `sessionQuery` 读会话头，不激活冷会话）；子目录归属父工程，取最长匹配。不属于任何工程时内容区只显示「暂无任务。」，问题按钮也隐藏。
- **工具**：`maw_board` / `maw_task` / `maw_deps` / `maw_plan_push` 默认按调用会话的工程取数。早先这四个工具取数时丢掉了 agent，落到部署级 `defaultDirectory`，于是 MAW 会话会读到别的工程甚至全局队列 —— 这是「发起任务时看到了所有任务」的根因。
- **启动指令**：写入工程 id 与工程名，并明确要求 MAW 模式调用工具时带 `project="<id>"`；MAW preset 的 persona 里也加了同一条边界。
- **风险 / 问题 / 迭代**：全局快照自带 `project_id`，取回后本地裁剪。

### 为什么不用 `maw board --project`

它确实能只统计一个工程，但会把本机共用的 `~/.maw/board/snapshot.json` 覆盖成该工程的范围（文件里 `filter_project` 会变），影响其它读者，例如 `maw serve` 的网页看板。轮询多个工程时还会来回翻写。所以取全局快照、本地裁剪。

## 工具条

工具条只在**当前工程已登记到 maw** 时出现按钮。判定方式是 `maw project list` 里有没有这个目录 —— 未登记的目录没有队列、没有 agent、没有 worktree，任何动作都没有落点，所以整组（启动 + 三个预览）一起隐藏，而不是显示成禁用。

### 启动按钮

它把「看板」从只读视图变成一次可执行的入口：点下去真的开一轮协作，而不是只把状态画出来。

- **可点条件**：当前工程有可开工的任务（依赖已完成的 `ready` / `backlog`），且该工程没有正在运行的 MAW 会话。
- **禁用条件**：已有 MAW 会话在执行 / 任务都在等依赖 / 工程还没有任务。
  - 执行中只是暂时状态：按钮旁不写文字，悬停时用原生 title 提示「任务执行中」（`disabled` 按钮在部分浏览器不派发悬停事件，所以套了一层带 title 的壳保证提示可见）。
  - 「没题可开工 / 工程没任务」是稳定状态，仍留在按钮旁写明，避免「按不动又不知道为什么」。
- **点击后**：Host 用 `ctx.sessionController.create({ cwd, agentPreset: 'maw' })` 建会话，再 `prompt` 投一条启动指令，然后跳到该会话。
- **防重**：`POST /launch` 在落库前重判一次可用性，并有按工程路径的启动中占位；同一工程连点只会开一个会话。

### 三个预览按钮

maw 有三十来个子命令，做成按钮的只有三条**默认无副作用**的。取舍标准是「点了最坏也只是多跑一次扫描」：

| 按钮 | 命令 | 为什么安全 |
|---|---|---|
| 自检 | `maw doctor` | 只读配置与协议版本 |
| 清理预览 | `maw prune` | 不带 `--yes` 时是 dry-run，只列不删 |
| 一致性检查 | `maw reconcile` | 不带 `--apply` 时只报告不修 |

其余命令刻意不做按钮：`submit` / `merge` / `block` / `task cancel` / `interrupt` / `reassign` / `lease release` / `project rm` 会把任务推到终态、动 worktree 或删登记，前提是任务处在某个特定状态、且后果需要人确认。这些交给 MAW 模式的 Agent 用工具调用，比在工具条上放一个危险按钮合理。

执行器有第二道闸：`isAllowedPreview` 按**参数**拦 `--yes` / `--force` / `--apply` / `--force-unmerged` / `--history`。白名单只到子命令粒度，靠参数黑名单兜住「预览命令被加上确认参数」这条缝。

## 界面

### 会话视图标签

会话主区顶部在「对话」「轨迹」旁边多一个「MAW看板」标签，点开即看板。它和对话共用同一块区域，不占额外屏幕。

从哪个工作区进来的会话，就看哪个工程：DSH 把每个工作区的会话放在按路径编码的目录下，插件据此把会话 id 反查成工作区路径，再与 maw 登记的工程比对；命中就把工程筛选默认选上。只登记了一个工程时，从其他工作区进来也默认落到它。

两个标签页：

- **看板** —— 以**任务状态**为泳道分组（可开工 / 进行中 / 合入中 / 待办 / 阻塞 / 已完成 / 已取消），卡面保留原泳道名与优先级。顶部三个筛选器（泳道 / 状态 / Agent）与「显示已完成」开关 —— 没有工程选择器，工程由会话工作目录决定。右侧栏列出风险与问题，按严重程度着色。
- **拓扑** —— 依赖 DAG，视觉与 maw board 一致：节点是 200×98 的卡片（左侧状态色条、id + 状态徽章、两行标题、负责人与 `P优先级`），连线为平滑贝塞尔并带中点圆点与箭头，视图外依赖画成虚线桩节点。横轴是依赖层级，悬停高亮直接相连的上下游；点击节点才在右侧打开详情，未选中时不占位。

### 任务详情

状态、负责人、泳道、优先级、合入序、尝试次数、依赖与上下游、写范围、读范围、验收条目、验证命令、分支、工作树、阻塞原因。

## 快捷键

按标签位置切换会话视图，序号与标签栏顺序一致（当前为 对话=1、轨迹=2、看板=3）。

| 运行环境 | 组合 |
|---|---|
| Desktop | `⌘1/2/3`、`⌥1/2/3`（Windows、Linux: `Ctrl+1/2/3`、`Alt+1/2/3`） |
| Web 浏览器 | `⌘⌥1/2/3`（`Ctrl+Alt+1/2/3`） |

浏览器把「单个修饰键 + 数字」留给自己的标签页切换，因此在 Web 运行时登记这些组合会被 shortcuts 服务直接拒绝；插件只在那两个平台上回避，Desktop 保持不变。

设置 → 快捷键 里每条命令的标题会跟着标签名走（如「切换到 看板」），按位置调整后不会出现序号与内容对不上的说明。

实现上，切视图没有公开 API（视图选择是 ui-conversation 自己的 store），所以借用标签栏上的 `data-conversation-tabs` —— 这是产品自己标注的稳定锚点 —— 按位置触发点击。

## MAW 模式

模式选择器里的一个 agent preset（id `maw`），与「标准模式」同构，只换了 persona 与工作流。

- **拆题**：题卡必须带 `id` / `title` / `writeScope` / `acceptance` / `verify`；`acceptance` 与 `verify` 是 maw 的硬要求，缺了压不进去。
- **压入**：`maw_plan_push` 把清单渲染成 blueprint 写到 `.multiagent/blueprint.maw-<时间戳>.toml`，先跑 `maw plan check`，再按 `apply` 决定是否 `plan apply --yes`。文件名带时间戳，不覆盖既有蓝图；apply 是增量合入，不带 `--reset`。
- **模型派发**：`maw_delegate` 读取当前工程可开工题卡，用题卡指定模型或能力等级的默认模型调用 DSH 原生 `subagent`。子智能体负责指定题号的领取和执行。能力等级随 `goal` 保存，`maw_task` 和看板详情会解析这项信息。配置见 [README](../README.md#配置)。
- **团队协作**：预设切到 MAW 时自动 `agentTeams.setEnabled(agent, true)`。因为切换事件是在会话写入过程中发出的，插件延后一拍再开，避免 append 重入；失败只记诊断。

诊断入口：`GET /dsh-maw/api/mode` 返回 `{ presetId, log }`，`log` 里每条记录包含触发来源、判定依据、团队开关结果。

## 三个工具

Agent 在会话里可以直接调用，拿到与界面一致的数据：

| 工具 | 用途 |
|---|---|
| `maw_board` | 看板摘要与筛选后的任务列表 |
| `maw_task` | 单个任务的完整详情 |
| `maw_deps` | 依赖拓扑；传 `focus` 看某任务的邻域 |

## maw 运行时

maw 是背景依赖而不是打包内容：二进制约 18MB 且分平台，塞进插件会让每个用户都下载所有平台。

安装器（`lib/maw-install.js`）做四件事：解析本平台的 release 资产 → 下载 → 按 `checksums.txt` 校验 sha256 → 解包安装并跑 `--version` 自证。官方包里的文件名是 `maw_<版本>_<平台>_<架构>` 而不是 `maw`，所以解包后统一改名。

失败策略是「宁可不装」：取不到 checksums、或 sha256 不匹配，直接中止并报错，不会留下一个无法验证的二进制。

`maw init`（在业务仓库里生成 `.multiagent/`）**不自动执行** —— 它会写用户的仓库，属于显式动作。

## 数据流

```
浏览器（看板 / 拓扑 UI）
      │  GET /dsh-maw/api/{board,graph,task,refresh}
      ▼
Host 半边  ──  spawn  ──►  maw <只读子命令> --json
      │                          │
      └────── 归一化 + 建图 ◄─────┘
```

Host 侧对命令结果做 5 秒缓存并合并并发请求，所以前端轮询不会反复拉起进程。

## 降级行为

| 情况 | 表现 |
|---|---|
| maw 未安装 | 界面提示未找到 maw 并给出查找过的路径，不白屏 |
| 当前目录不是 git 仓库 | 退回配置的项目路径，再退回 maw 项目登记 |
| 命令超时或输出异常 | 该数据源标为降级，其余部分照常渲染 |
| 依赖图有环 | 红色虚线标出并单独列出，其余节点正常渲染 |
| 依赖指向不存在的任务 | 单列为悬空依赖，不静默丢弃 |

## 已知限制

- 依赖 maw 的 JSON 输出格式，但不绑定具体版本；字段读取走容错访问器，上游改字段名时对应展示留空而不报错。0.4.1 与 0.5.0 均已实测通过。
- 版本跟进只报告「本机是否落后于最新 release」，不会自动升级；装新版是显式动作。
- 拓扑图超过 `maxGraphNodes` 时默认只渲染未完成子图。
- 不做 `maw status report` 心跳上报（写操作）。
